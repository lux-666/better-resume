# Phase 3 演示脚本

1. 打开“演示档案与真实记录回放”，选择双项目、边界或矛盾档案；确认当前运行标记是 LLM 还是 DEMO。
2. 创建 Session 并开始。候选人阅读开场，再按本目录 JSON 的 script 中对应话题输入回答；boundary 档遇到依据及更深问题使用 boundary 文本。
3. 提交后观察整理回答、准备下一问、保存结果和已用时间。阶段来自执行事件，重试时不重复提交。
4. 在审核模式打开技术视图，查看 Trace、Agent/Model/Tool/State 时间轴、模型请求与重试的区别、token 可用性及 p50/p95 样本数。
5. 打开报告预览，展示全部原话、五层深度、未展开线索、支持与待核实结论。完成后观察独立的叙述生成，展示招聘方与候选人两版建议。
6. 如需恢复说明，等待过程中刷新；仍在执行时继续观察，失败或超时后使用原命令重试。
7. Provider 不可用时，使用明确标记“回放·非实时”的已保存记录；无完整记录时界面会说明不可用。

## 准备与门槛

- 本地链路：`npm run eval:phase3 -- --demo`。
- 真实模型深度标注：`npm run eval:phase3 -- --depth`。
- 真实演示与交互：`npm run eval:phase3`，或 `--profile demo-boundary` 等单档运行。
- 只有完整通过自动 Gate 的实际运行记录才会写入 `replays/`；回放保留原运行模式，不伪装为实时。
- 完整轮数由 Agent 与护栏决定，最多 15 问；路演可选取约 4–6 轮的片段，不能将预期片段长度作为实际完成保证。
- 真实模型连续 3/3、原发布场景与人工 Rubric 是独立门槛。模拟 Provider、本地 Demo 或自动引用检查不能替代人工评审。
