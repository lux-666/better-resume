# Task 1.4：小规模内部体验验收

[返回 Phase 1](README.md)

| 属性 | 值 |
| --- | --- |
| 状态 | Blocked by Task 1.2 |
| 优先级 | P1 |
| 依赖 | 真实模型行为 Gate 连续三次通过 |

## 目标

验证自动化难以可靠判断的连贯性、审讯感、关键线索漏追和最终 Candidate Report 可用性，决定产品是否具备进入 Phase 2 的条件。

## 测试范围

- 3–5 名内部测试者；
- 每人完成两次 Session；
- 使用同一已通过 Gate 的模型配置；
- 至少覆盖一个强回答、一个弱回答和一次 Claim 修正；
- 不在测试过程中人工修改 InterviewState 或跳过 Validator。

## 每个 Session 记录

| 指标 | 记录方式 |
| --- | --- |
| 完成轮数与时间 | 自动记录 |
| 重复或无关问题 | 测试者标记轮次 |
| 关键线索漏追 | 标记 Answer 中线索及后续 Questions |
| 过早结束或无效拖延 | 测试者判断并附 Transcript |
| grounding 错误 | 对照 Evidence sourceQuote |
| Report 可用性 | 1–5 分及一句原因 |
| 审讯感与连贯性 | 1–5 分及一句原因 |

只把跨两个以上 Session 重复出现，或任何单次 Critical grounding/数据问题，转成工程任务。单个偏好意见不直接进入开发。

## 交付物

- 匿名化 Session 结果表；
- 阻塞问题的最小 Transcript；
- Phase 1 是否通过的结论；
- 需要进入 Task 1.3 的明确问题列表。

## 验收标准

- grounding 违规和跨候选人数据问题为 0；
- 没有未归档的阻塞性过早结束、重复追问或关键线索漏追；
- 每个阻塞问题都有 sessionId、轮次和最小 Transcript；
- 产品负责人明确记录 Go 或 No-Go；
- No-Go 时回到 Task 1.3，修复后重新运行行为 Gate。

## 不做

- 对外 Beta；
- 招聘决策有效性研究；
- 大规模统计显著性实验；
- 根据单个测试者偏好修改产品。
