# Task 4.4：本地使用、历史会话与稳定性

[返回 Phase 4](README.md)

## 目标

产品通过 GitHub 分发，用户下载到本机运行。Web/API、SQLite 数据和历史记录由本机用户持有；对话与 embedding 仍可调用用户配置的模型 API。这不是托管的联网招聘服务，不引入邮箱登录、验证码、一次性候选人链接、账户归属或跨账户权限校验。

## 本地历史会话

- 复用已有 SQLite `sessions`、`answer_commands`、`telemetry_traces` 和 `report_narratives`；不另建一份历史状态。
- 首页提供历史列表，显示候选人/会话名称、岗位、创建/更新时间、进行中/已完成状态，按更新时间排序。
- 从历史打开未完成 Session，可查看完整对话并继续；已完成 Session 可查看报告、对话和技术视图。
- 关闭页面、清除浏览器缓存、重启服务后，历史仍从数据库读取；localStorage 仅记住最近打开的 Session。
- 默认持续保留，由用户主动删除或导出，不做 24 小时访问失效或 90 天自动清理。
- 删除 Session 时一并清理其 Answer Command、Trace、报告和后续派生索引；公共知识卡片与索引保留。
- 文档说明数据库位置、备份与恢复，以及更换 `DATABASE_PATH` 会切换所见历史。

## 模型故障与恢复

- 可选 `LLM_FALLBACK_MODEL`，用于主模型 Provider 重试用尽、超时或模型输出无法通过业务约束的情况。
- 主模型失败后，备用模型使用同一 frozen State 与 answer 重试；一次 Answer 只提交一次状态变化。
- Trace 记录主备模型各自的 token、耗时、错误和最终采用者。
- 备用模型仍失败，保留回答并允许重试；保持现有幂等键、版本和租约机制。
- UI 清楚显示正在恢复的回答或失败重试状态。

## 本机运行与可观测性

- 默认监听 `127.0.0.1`，提供完整的下载、安装、配置、启动、升级和数据备份说明。
- 延迟统计分别展示成功回答的端到端 p50/p95、样本量、Provider 错误率、超时和备用模型采用率。
- 以个人本机使用和少量会话为验收场景，不设置 20 活跃 Session 的托管服务容量目标。
- 可选面试时长预算 20–60 分钟，到时优先结束；15 轮硬上限保留。

## 验收

- `npm test`、typecheck、build 通过；固定 Profile 与发布场景无新增阻塞问题。
- 关闭/重开页面及重启进程后，历史记录、已提交回答与报告保持完整，未完成面试可继续。
- 导出、备份/恢复和删除行为有明确验证，删除后关联数据无残留。
- Provider 错误、超时及模型输出失败后恢复正确，无重复 Evidence、无部分 State。
- 在全新本地目录按照 README 可完成安装、配置模型、面试、查看历史与报告。

## 明确不做

- 邮箱/验证码登录、候选人访问 token、账户或组织权限、多租户、SSO；
- 托管联网服务部署与跨账户隔离验收；
- 视频/语音面试、候选人跨 Session 画像、模型微调。

Evidence 原话来源、模型输出、问题格式、Answer 幂等与事务等业务完整性约束继续保留；它们用于防止错误报告或数据损坏，不属于联网服务身份校验。
