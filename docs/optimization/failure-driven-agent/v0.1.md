# 失败驱动 Agent 优化 v0.1

## 结论

v0.1 没有增加新 Agent、长期模型记忆或 Lead/Probe 状态。它把真实模型失败分别修在 Prompt、调用上下文、工具契约、Core Validator、固定 Profile 和 Evaluation Runner 的最低正确层，并保留确定性边界。

效果不是“模型看起来更聪明”，而是同一 `openai_compatible / gpt-5.6-terra` 配置下，六个固定 Profile 的完整真实模型 Gate 在最后一次行为修改后连续 **3/3 全部通过**。

## 最原始方案的问题

初始实现已经有 Report Agent、Interview Agent、工具调用和 Core 校验，但失败处理仍有几个明显缺口：

- Prompt 没有明确具体线索的追问优先级、weak/contradicted 是合法结论、重复回答后的停止条件；
- 模型看不到确定性的 completion 结果和 saturated field；
- Tool Schema 只约束 JSON 形状，没有把 disposition/polarity、claim、active-project field 和 competency 的业务边界讲清；
- 工具失败只返回笼统错误，模型无法在当前调用内修正；
- contradiction 被重复否认后可能重新打开；
- strong Profile 的固定回答不具备它声称应有的具体证据；
- Runner 失败输出缺少 Profile、阶段、重试次数和最小 Transcript，导致优化只能猜。

## v0.1 方案

### Prompt

- 遇到具体命名机制或明确选择时立即纵向追问一次；
- weak 或 contradicted 可以是最终结论，不为追求 support 无限追问；
- 同一字段连续两次得到相同回答后切换或结束；
- `completion.allowed` 为真时请求结束，被拒绝时只调查一个 blocker；
- denial/contradiction 必须生成绑定 exact claim ID 的 invalidate Evidence。

### 调用上下文

- Interview Agent 获得确定性的 completion 结果；
- 只携带最近四轮对话，长期事实进入 `InterviewState`，不复制第二套模型记忆；
- 显式提供 `saturatedFieldIds`、`allowedClaimIds` 和 active-project `allowedReportFields`。

### Tool 与 Core

- Schema 描述和工具错误返回可操作的 exact ID/competency 边界；
- 模型可在同一次临时 Agent 调用中修正一次非法 Tool Call；
- Core 继续拒绝无来源引用、跨项目字段、competency 不匹配、语义提升和非法完成；
- contradiction lifecycle 在首次否认时打开，后续有依据的澄清进入 resolution，不重新打开；
- 问题标点做最小规范化，多问题和评价性话术仍由 Guard 拒绝。

### Profile 与 Runner

- strong Profile 改为包含 ownership、mechanism、measurement 和 failure 的逐字可引用回答；
- Provider 暂时失败只重试一次；
- Runner 输出 category、profile、stage、retryCount 和最小 Transcript；
- Provider 错误、模型输出错误和行为 Gate 错误使用不同退出语义。

## 效果

| 指标 | 原始方案 | v0.1 |
|---|---|---|
| 完整真实模型 Gate | 存在 hard-limit 未完成、非法字段、语义错配和漏追线索 | 六 Profile 连续 3/3 全部通过 |
| strong Profile | 具体 Evidence 不足，曾到 15 轮仍未完成 | 连续三次通过：9、10、12 轮 |
| weak Profile | 已形成 weakness 仍可能机械追问 | 10 轮通过 |
| contradictory Profile | 重复否认可能重开 contradiction | 14 轮通过且 lifecycle 回归通过 |
| vertical-depth Profile | `hybrid search` 线索可能被跳过 | 13 轮通过 |
| 确定性验证 | 失败边界覆盖不足 | 全仓测试 32/32、typecheck、build 通过 |
| 失败可定位性 | 顶层错误文本 | 精确到 Profile、stage、retryCount 和最小 Transcript |

无法诚实给出一个统一“提升百分比”：原始阶段不是同一基线重复运行，而且修复对象包含行为正确性、语料、状态机和可观测性。v0.1 的有效数字是 **3/3 完整 Gate、六类 Profile 全覆盖、32/32 确定性测试**，不是虚构的综合分数。

## 没有做什么

- 没有提高 15 轮 hard limit；
- 没有删除 Profile 或放宽 grounding/completion Gate；
- 没有为具体关键词硬编码固定问题；
- 没有新增长期模型记忆、Lead、Probe、utility 或第二套调度状态；
- 没有把模型输出静默改写成合法业务事实。

## 适用边界

结果只对当前固定 Candidate Fixture、Role、Prompt、工具契约和模型配置成立。更换模型、Provider、Prompt、上下文投影或 Validator 后，完整 Gate 必须重新计数。

详细失败与修复 Trace 见 [Task 1.3](../../phase/phase1/task-1.3-failure-driven-optimization.md)。
