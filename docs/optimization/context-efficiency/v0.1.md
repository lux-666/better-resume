# 上下文成本优化 v0.1

## 结论

v0.1 删除了三类确定的浪费：Report Agent 不再读取所有项目，Interview Agent 不再读取与 Report Agent 相同的完整 Report，并把结构化提取交给较快的 Terra、面试决策保留给较强的 Sol。`InterviewState` 仍是唯一权威状态，`read_report` 工具名和两次调用结构保持不变。

上下文投影使同一双项目 fixture 的两次 `read_report` 序列化内容从 **5676 字符降到 3649 字符，减少 35.7%**。真实六 Profile 矩阵中，`Report=Terra / Interview=Sol` 相对 `Sol/Sol` 进一步实现：

- input + output token 减少 **21.4%**；
- 模型请求减少 **19.6%**；
- 模型累计延迟减少 **41.5%**。

静态分流已获准上线。质量横向分数因旧 Gold 和不同面试轨迹而失效，这个缺陷继续保留为评测修复项，但不再阻断本次以时间和 token 成本收益为目标的上线决策。

## 最原始方案

每次候选人回答会产生两次独立模型调用：

```text
Report Agent    → read_report(full report) → edit_report
Interview Agent → read_report(full report) → ask_candidate | finish_interview
```

原始 `read_report` 对两个 Agent 都序列化：

- 所有 Project 的描述、技术、成果和 Claims；
- 所有 Report fields；
- 所有字段的 Evidence statement、polarity 和 sourceQuote；
- 所有 Contradictions。

问题很直接：Evidence 和 `sourceQuote` 随会话增长，同一个大对象在一轮中发送两次，而两个 Agent 实际需要的信息不同。

## v0.1 方案

### Report Agent：按 Project 切片

Report Agent 的 `read_report` 只返回当前 Project：

- Project 元信息和相关 Claims；
- 当前 Project 的全部 Report fields；
- 这些 fields 引用的 Evidence 和 sourceQuote；
- 当前 Project 相关 Contradictions；
- 当前 focused field ID。

切片边界选择 Project，不选择单个 field。原因是一个回答可以同时更新同一项目的 ownership、mechanism、measurement 和 failure；切到单 field 会破坏已有的 multi-field Evidence 能力。

### Interview Agent：轻量跨项目索引

Interview Agent 的 `read_report` 返回：

- 所有 Project 的轻量 field index：ID、名称、描述、重要性、状态、摘要和 Evidence 数量；
- 每个 Project 的开放 Contradiction ID；
- 一个 focused Project 的元信息和 Claims。

它不再读取完整 Evidence 历史和 `sourceQuote`。最新回答、最近四轮、completion 和 saturated fields 仍通过现有调用输入提供。

### Agent 静态分工

生产服务从环境变量读取两个 Agent 的模型，不把模型名称硬编码进业务代码：

```dotenv
LLM_REPORT_MODEL=gpt-5.6-terra
LLM_INTERVIEW_MODEL=gpt-5.6-sol
```

```text
Report Agent    → Terra → read_report → edit_report
Interview Agent → Sol   → read_report → ask_candidate | finish_interview
```

这不是基于 confidence 或回答复杂度的动态 Router。模型分工在进程启动时固定，Provider、Base URL 和凭据保持一致。运行信息、Step execution trace 和 model span 分别记录实际模型，避免上线后只看到一个含糊的默认 `modelId`。

### 保持不变

- `InterviewState` 仍保存完整 Candidate、Report、Evidence、Turns、Contradictions 和 Traces；
- 两个 Agent 都从同一权威 State 构建视图，没有新增缓存表或第二份记忆；
- 工具名仍是 `read_report`，避免无意义破坏 harness 协议；
- Report edit、Question Guard、Completion Validator 和持久化流程不变。

## 体积对比

测量状态：当前双项目 fixture，完成一次回答后，对三个投影执行同一 `JSON.stringify(...).length`。

| 每次读取 | 原始 full report | v0.1 | 减少 |
|---|---:|---:|---:|
| Report Agent | 2838 字符 | 1636 字符 | 42.4% |
| Interview Agent | 2838 字符 | 2013 字符 | 29.1% |
| 每轮两次合计 | 5676 字符 | 3649 字符 | 35.7% |

计算：

```text
Report Agent:    1 - 1636 / 2838 = 42.4%
Interview Agent: 1 - 2013 / 2838 = 29.1%
每轮合计:       1 - 3649 / 5676 = 35.7%
```

随着 Evidence 和 sourceQuote 增长，Interview Agent 不携带这些历史的收益预计会扩大；这是推断，尚未用长 Session token telemetry 验证。

## 真实 token 与时间对比

测量日期：2026-09-02。三种策略使用同一个 `openai_compatible` Provider，各执行一次全部六个固定 Profile。

| 策略 | Model requests | Input tokens | Output tokens | Token 合计 | Model latency |
|---|---:|---:|---:|---:|---:|
| Sol / Sol | 184 | 273,728 | 28,963 | 302,691 | 1,462.2 s |
| Terra / Sol | 148 | 216,755 | 21,180 | 237,935 | 854.8 s |
| 改善 | -19.6% |  |  | **-21.4%** | **-41.5%** |

这里的“成本收益”指真实 token 用量下降。当前 adapter 单价配置为 0，因此没有伪造人民币或美元金额；当 Provider 按 input/output token 计费时，实际账单收益应按对应单价分别计算。

## 验证

- 新增断言：Report Agent 视图包含当前 Project，不包含其他 Project 和 Claim；
- 新增断言：Interview Agent 保留全部 Project 索引，但不包含 `sourceQuote` 和历史回答正文；
- 三种模型策略的六个旧行为 Gate 均通过，Critical/Major 为 0；
- 生产 Server 已分别创建 Report runtime 和 Interview runtime，健康接口、页面和 Step execution trace 暴露实际模型分工；
- 全量测试 43/43 通过；
- TypeScript typecheck 和生产构建通过。

## 尚未证明

- 35.7% 是上下文字符体积下降，不能直接当成 token 降幅；真实矩阵测得的 token 降幅是 21.4%；
- 尚未配置真实模型单价，因此只能报告 token 成本收益，不能报告货币金额；
- cache read 在三组中差异较大，单次矩阵不足以证明长期 prompt cache 收益；
- 旧 Field precision/recall 因 Gold 漏标合法多字段和策略轨迹不同而失效，不能用来判断 Terra 与 Sol 的真实质量差异；
- 没有验证 `previous_response_id` 或 provider 侧会话复用；
- 没有合并两个 Agent 调用。

上线后的继续验证使用确定性的 frozen Report replay 和逐 Turn actual-vs-Gold 明细，不回滚已经确认的成本与时间收益。
